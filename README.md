# امتثال — Emtithal

منصة ذكاء اصطناعي للامتثال الاستباقي وذكاء القرار لشركات خدمة الحج والجهات الرقابية.

هذا مستودع نموذج تجريبي (MVP) لهاكاثون. المصدر الوحيد للحقيقة على مستوى المنتج هو
[`EMTITHAL_MASTER_SPEC.md`](./EMTITHAL_MASTER_SPEC.md)، والنطاق التنظيمي للنموذج التجريبي
محدد في [`MVP_REQUIREMENTS.md`](./MVP_REQUIREMENTS.md). لا يتضمن الكود أي متطلبات أو أوزان
أو قرارات رقابية غير موجودة في هذين الملفين.

## التشغيل محليًا

يتطلب Node.js 20+.

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`. من الصفحة الرئيسية اختر «دخول تجريبي — شركة الحج» (مع اختيار
دور) أو «دخول تجريبي — وزارة الحج والعمرة» — لا يوجد نظام مصادقة إنتاجي في هذا العرض، وهذا
مقصود ضمن نطاق الهاكاثون.

أوامر أخرى:

```bash
npm run build   # بناء إنتاجي + فحص TypeScript
npm run start   # تشغيل البناء الإنتاجي
npm run lint    # ESLint
npm test        # اختبارات محرك الامتثال ومحرك محاكاة القرار (node:test عبر tsx)
```

## البنية التقنية

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4. واجهة عربية بالكامل
(`dir="rtl"`, خط IBM Plex Sans Arabic). لا توجد قاعدة بيانات أو خادم API خارجي — كل شيء يعمل
داخل تطبيق Next.js واحد، بمعمارية طبقات واضحة الفصل:

```
src/
  lib/
    types.ts               تعريفات الكيانات (Requirement, Evidence, Gap, Risk, ...)
    labels.ts               تسميات عربية وألوان موحّدة للحالات/المخاطر/الثقة
    data/                    البيانات التوضيحية (شركة، متطلبات، أدلة، فجوات، مخاطر، تنبيهات...)
    engine/                  المنطق الحتمي المعزول عن أي واجهة
      scoringEngine.ts        محرك الامتثال: النتيجة، الحالة، الخطر، الثقة
      capabilityEngine.ts     مؤشرات القدرة (صيغ موثّقة، لا يولّدها الذكاء الاصطناعي)
      decisionEngine.ts       محرك محاكاة القرار (جدول قواعد + بدائل + توصية)
      __tests__/               اختبارات node:test للمحركين أعلاه
    store/
      demoStore.tsx            حالة الجلسة التفاعلية (React Context + localStorage)
    hooks/
      useCompanyCompliance.ts تجميع مخرجات المحرك لواجهة الشركة
  components/                مكونات قابلة لإعادة الاستخدام (شارات، بطاقات، تخطيط، نماذج)
  app/
    page.tsx                 الصفحة الرئيسية / اختيار الدور
    company/...               تجربة الشركة (لوحة، امتثال، أدلة، فجوات، خطة تحسين، محاكاة قرار، تنبيهات)
    ministry/...              تجربة الوزارة (مركز تحكم، شركات، معايير، مخاطر، مراجعات، تنبيهات)
```

### الفصل بين المنطق الحتمي والذكاء الاصطناعي

طبقًا لـ`EMTITHAL_MASTER_SPEC.md` (§17، §26، §28): النتائج الرقمية للامتثال **لا** تُولَّد من
نموذج لغوي. كل حساب رقمي — نتيجة المعيار، الحالة، مستوى الخطر، النتيجة الإجمالية المرجّحة،
مؤشرات القدرة، وتوقع أثر القرار — يمر عبر دوال حتمية وقابلة لإعادة الإنتاج في `lib/engine/*`،
موثّقة بالتعليقات وموثّقة اختبارات في `lib/engine/__tests__`. طبقة «الذكاء الاصطناعي» في هذا
العرض التجريبي تظهر كنصوص تفسيرية (شرح الفجوة، تحليل الدليل، تفسير المحاكاة) مبنية على مخرجات
المحرك الحتمي — لا تُنشئ الأرقام ولا تتجاوزها، تمامًا كما يتطلب المستند المرجعي.

## ما هو حقيقي مقابل ما هو تجريبي/محاكى

| الجانب | الحالة |
|---|---|
| محرك حساب النتيجة والحالة والخطر (`scoringEngine.ts`) | منطق حتمي حقيقي، قابل للاختبار وإعادة الإنتاج |
| محرك مؤشرات القدرة (`capabilityEngine.ts`) | صيغ حتمية موثّقة تعمل على بيانات الشركة الهيكلية |
| محرك محاكاة القرار (`decisionEngine.ts`) | تحليل قواعد حتمي («AI-Assisted Impact Forecasting» — MASTER_SPEC §26)، **ليس** نموذج تنبؤ إحصائي مدرَّب على بيانات تاريخية، وليس قرارًا رقابيًا رسميًا |
| المعايير الخمسة وأوزانها (20% لكل معيار) | تكوين تجريبي للعرض فقط — **ليس** وزنًا رسميًا معتمدًا من الوزارة (مُعلَّم بوضوح في كل الواجهات) |
| رفع الأدلة | يعمل فعليًا داخل الجلسة (قراءة اسم/نوع/حجم الملف)، لكن **لا يوجد تخزين أو معالجة مستندات فعلية على خادم** — تحليل الذكاء الاصطناعي للملفات المرفوعة تجريبيًا نص توضيحي معلَّم بوضوح، وليس استخراجًا حقيقيًا من محتوى الملف |
| بيانات الأدلة/الفجوات/المخاطر لشركة النور (الشركة التجريبية الأساسية) | بيانات توضيحية ثابتة، لكنها متسقة رياضيًا مع محرك الامتثال (الحالات والنتائج محسوبة فعليًا من حالة أبعاد الأدلة) |
| الشركات الخمس الأخرى في مركز التحكم الرقابي | ملخصات ثابتة لأغراض عرض لوحة الوزارة فقط — لا تحتوي بيانات تفصيلية على مستوى المعيار (موضّح داخل الواجهة) |
| تسجيل الدخول / الأدوار | دخول تجريبي بدون كلمة مرور — لا توجد بنية مصادقة إنتاجية (خارج نطاق الهاكاثون حسب المواصفة) |
| حالة الجلسة (رفع أدلة، تغيير حالة إجراء، تشغيل محاكاة، فتح تذكرة اعتراض) | تُحفظ في `localStorage` الخاص بالمتصفح فقط — لا يوجد خادم أو قاعدة بيانات خلفية |
| «تفعيل/إيقاف معيار» في شاشة الوزارة | تفاعل عرضي (حالة مكوّن محلية) لإظهار تجربة الحوكمة، ولا يُعاد حساب نتائج الامتثال المعروضة تلقائيًا بناءً عليه ضمن نسخة الهاكاثون |

## المعايير الخمسة المعتمدة

مأخوذة حرفيًا من `MVP_REQUIREMENTS.md` (يُستخدم فيها معرّف `CR-00X` كما ورد في ملف
المتطلبات):

1. **CR-001** — صناعة تجربة ضيف الرحمن
2. **CR-002** — تبني المفاهيم الحديثة والترسيخ المعرفي
3. **CR-003** — ضمان حفظ حقوق ضيف الرحمن *(معيار حرج — Critical Gate)*
4. **CR-004** — التعايش مع رحلة ضيف الرحمن ورصد التجربة
5. **CR-005** — توثيق فعاليات ومبادرات فريق السعادة

## القيود المعروفة

- بيانات تفصيلية على مستوى المعيار متاحة لشركة تجريبية واحدة فقط (شركة النور)؛ باقي الشركات
  في لوحة الوزارة ملخصات ثابتة.
- لا يوجد استخراج فعلي لمحتوى ملفات PDF/Excel المرفوعة — العرض التجريبي وظيفي (اسم/نوع/حجم
  الملف وربطه بمعيار) دون تحليل محتوى حقيقي.
- تعديل الأوزان أو تفعيل/إيقاف معيار في شاشة إدارة المعايير لا يُعاد حسابه في محرك الامتثال
  ضمن هذه النسخة.
- لا يوجد نظام مصادقة أو صلاحيات إنتاجي.
- الحالة التفاعلية محلية للمتصفح (`localStorage`) ولا تُشارك بين الأجهزة أو المستخدمين.

## خطوة تالية مقترحة لمراجعة Codex

مراجعة `lib/engine/decisionEngine.ts` (جدول حساسية القرارات) و`lib/data/requirements.ts`
(حالات أبعاد الأدلة والنتائج المشتقة منها) للتأكد من أن كل نص تفسيري بالعربية متسق منطقيًا مع
الأرقام التي يحسبها المحرك الحتمي، ثم توسيع تغطية بيانات الشركات الأخرى في مركز التحكم
الرقابي إذا تقرر عرض تفاصيل على مستوى المعيار لأكثر من شركة واحدة.
